\subsection{C2 -- Solar lensing on a duon export window}\label{app:c2}
\paragraph{Question.} Does a cited solar boundary/export window support the predicted shell qualification, push/pull split, torsional residual, emitted wavelet-packet witness, and grazing-incidence lensing rendering when the export class is read on the duon family?

The focus is the same AOD spine used elsewhere: fix the row on the export ledger first, then attach the familiar bending value only after the row is fixed.

\paragraph{Cited input block.} The render-layer solar radius is anchored to NASA's solar glossary and Sun facts material, which give $R_\odot = 695{,}700\ \mathrm{km}$ as the standard solar radius.\footnote{NASA Science, \href{https://science.nasa.gov/universe/glossary/}{Universe Glossary -- solar radius}; NASA Science, \href{https://science.nasa.gov/sun/facts/}{Sun: Facts}.} The heliocentric mass parameter and speed of light used in the rendering layer are taken from the JPL Solar System Dynamics astrodynamic parameters page, which records $GM_\odot = 1.32712440041279419\times 10^{20}\ \mathrm{m^3\,s^{-2}}$ and $c=299{,}792{,}458\ \mathrm{m\,s^{-1}}$.\footnote{JPL Solar System Dynamics, \href{https://ssd.jpl.nasa.gov/astro_par.html}{Astrodynamic Parameters}.}

These cited values instantiate the rendered benchmark only. After the reduction below, the row is fixed in the default calculus and the lensing value is attached afterward.

\paragraph{Declared reduction.} Let $O_\odot$ be the cited Sun ominion on the export window $\omega_{\mathrm{sol,lens}}$. The long-range boundary class is reported on the duon family:
\[
\texttt{duon:2:1:7}.
\]
The emitted wavelet packet on the cited boundary is the duon packet witness. The rendered solar bending value is not used as a premise of the row; it is attached only after the export packet row has been fixed.

\paragraph{Calculation block.} This section keeps the AOD line visible and keeps the familiar bending value in the rendering layer.

\textit{Step 1: source ominion and export class.} Reduce the Sun to the source ominion $O_\odot$ on the cited export window and fix the open-seat export class on the duon family:
\[
O_\odot \longrightarrow \texttt{duon:2:1:7}.
\]
On the same boundary ledger the packet witness is read as an emitted wavelet packet / duon packet.

\textit{Step 2: export-row fixation.} On the cited export window, the row is fixed by the same bookkeeping used in the earlier duon export examples:
\[
e_\alpha,e_\Omega,f \longrightarrow q_{\mathrm{eff}}, T_{\mathrm{tors}}, \text{packet witness}, \text{shell qualification}.
\]
For the present line, the compact export row is carried with
\[
q_{\mathrm{eff}} = +\frac{1}{2},\qquad T_{\mathrm{tors}} = 2,
\]
with a qualified emitted duon packet on the cited boundary.

\textit{Step 3: render-layer grazing benchmark.} After the row is fixed, attach the familiar weak-field grazing deflection benchmark by
\[
\delta_{\mathrm{graze}} = \frac{4GM_\odot}{c^2 R_\odot}.
\]
With the cited render-layer anchors
\[
GM_\odot = 1.32712440041279419\times 10^{20}\ \mathrm{m^3\,s^{-2}},\qquad R_\odot = 6.957\times 10^8\ \mathrm{m},
\]
this gives
\[
\delta_{\mathrm{graze}} \approx 8.44\times 10^{-6}\ \mathrm{rad} \approx 1.751\ \mathrm{arcsec}.
\]
The benchmark is therefore attached as a rendering of the same export packet ledger rather than as an imported premise.
