\subsection{Identity and counterfactual audit}

The H-1 identity packet is part of every occurrence and trace hash.  A
counterfactual H-2 identity changes the identity and occurrence hashes and is
rejected by the H-1 gate unless it is declared as its own scoped occurrence.
The direct-return topology may recur, but the scoped occurrence does not.

The fail-closed audit also rejects:
\begin{itemize}
  \item a non-binary \(Q_4\) state;
  \item a Hamming-distance-two edge;
  \item disconnected event order;
  \item a fifth local edge slot;
  \item a non-normalized or zero-denominator kernel;
  \item support-family identifiers reused as local edge/event identifiers;
  \item opened target input or changed execution mode;
  \item a read-only trace/hash mismatch.
\end{itemize}
The unchanged control passes.


\subsection{Exact schema, source-chain, and detector admission}

The native geometry and exact kernels above are admitted only after a
fail-closed packet audit.  Every source and generated CSV has one ordered
schema.  An unknown, missing, duplicated, or reordered column is a failed
packet rather than an ignored extension.  This closes the target quarantine at
the packet boundary: Balmer, SI-duration, target-value, residual, and score
fields are not members of any native H-1 packet schema.

The source chain is verified before packet construction:
\[
\begin{aligned}
\text{H-1 occurrence plan}
&\to
\text{frozen }3{:}3{:}6\text{ gate}
\to
\text{C6 support-policy card}
\\
&\to
\text{released temporal-type rows}.
\end{aligned}
\]
Exactly one H-1 plan row and exactly one declared core occurrence are admitted.
The prior consequent-form manifest, its passing gate statuses, and every file
record are hash-verified.  The carried
\texttt{hydrogen\_\allowbreak occurrence\_\allowbreak pending} text is retained only as a historical
pre-H-1 planning status; it is not interpreted as the current gate state.

The occurrence packet hash is propagated through the local-state registry,
edge inventory, kernel audit, execution ledger, read-only trace, and returned-current
detector.  State-row hashes and the admitted-edge row hash are likewise bound
where those rows are consumed.  The read-only packet therefore identifies not
only the occurrence ID but the exact occurrence and execution packets from
which it was built.

After the detector row is written, a separate evaluator verifies its exact
schema, attached row hash, occurrence and identity bindings, returned-current
classification, two-token witness count, and every downstream closed status.
Malformed values such as an out-of-range edge slot, non-rational weight,
missing packet, or zero denominator return a structured failed audit; they do
not escape as uncontrolled exceptions.

The release audit contains three counterfactual families:
\begin{itemize}
  \item source counterfactuals for duplicated or semantically opened planning
        and carried source rows;
  \item packet counterfactuals for native-field mutations, malformed packets,
        and target/metric-field insertion in every packet class;
  \item detector counterfactuals for schema extension, identity/occurrence
        drift, altered classification, changed token count, and opened
        downstream status.
\end{itemize}
Each counterfactual is regenerated, rehashed, and passed through the same
admission evaluator.  The gate passes only when every expected rejection and
the unchanged controls agree with the frozen audit.
