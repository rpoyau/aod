# v40.03r07.3.4-delta2 corrective authoring evidence

## Scope and classification

This is a release-infrastructure correction to the v40.03r07.3.4 candidate.
It addresses the two findings that remained `APPLIED_UNVERIFIED` after the
independent review of delta1:

- `R0733-REV-003`: complete, verified four-dependency fallback;
- `R0733-REV-004`: deterministic REVIEW-to-GO transition with a bound GO
  decision and validation of the emitted successor.

No scientific source, Manual I source, Manual II source, shared source, or PDF
payload is changed by this corrective pass. Hydrogen r08 remains blocked.

## AF protocol commitments

### C1 — exact locked-fallback identity

Let the dependency order be

`D = (AF, AFC, GM, AOD)`.

For a carry-forward lock fallback, row `i` is admitted only when it is exactly

`(dependency_id, release_metadata_path, release_metadata_sha256,
resolved_release_supersedes_bootstrap)`

for repository `i` in the already verified canonical lock. The referenced file
must also exist and reproduce the declared SHA-256. Merely naming four
repositories, setting `complete=true`, or preserving the order is insufficient.

Implemented by:

- `tools/validate_upstream_release_lock.py::_validate_locked_fallback_dependencies`;
- the carry-forward validation branch in
  `tools/validate_upstream_release_lock.py`.

### C2 — fallback commit atomicity

A network/API failure now creates the receipt, fallback snapshot, and status in
an isolated full-tree stage. The staged upstream state is semantically
validated before the complete `governance/` tree is replaced. A failed
validation or replacement restores the prior tree. No unvalidated fallback
packet is committed to the candidate.

Implemented by:

- `tools/resolve_github_releases.py::_record_nonblocking_fallback_in_place`;
- `tools/resolve_github_releases.py::_commit_governance_atomic`;
- `tools/resolve_github_releases.py::_record_nonblocking_fallback`.

### C3 — GO-decision content binding

Let

`h_GO = SHA256(canonical_bytes(cycle/GO_DECISION.json))`.

Every transition whose `to_phase` is `GO` must carry
`bound_digests.go_decision_sha256 = h_GO`. The concrete GO state must also carry
`decision_path = cycle/GO_DECISION.json` and `decision_sha256 = h_GO`.

The transition schema conditionally requires the digest, and the phase
validator rejects any mismatch among the decision bytes, transition row, and
cycle state.

Implemented by:

- `cycle/schemas/transition-record.schema.json`;
- `cycle/schemas/cycle-state.schema.json`;
- `tools/run_review_go_transition.py`;
- `tools/validate_phase_bundle.py`.

### C4 — emitted GO successor validation

The REVIEW-to-GO command now validates the emitted ZIP through the canonical
`validate_complete_bundle` entry point and separately through
`validate_phase_bundle`. Publication fails unless both reports pass and agree.
The command still opens r08 only in the emitted GO state and does not promote a
new stable baseline in that same transition.

## Falsification tests

The tests include the following negative cases:

1. swapping one carry-forward fallback path with another dependency is rejected;
2. a GO transition without `go_decision_sha256` is rejected by schema;
3. a GO decision whose digest differs from the transition binding is rejected;
4. the REVIEW-to-GO command is required to invoke canonical complete-bundle
   validation as well as phase validation;
5. staged fallback generation is semantically validated before atomic commit.

Primary executable evidence:

- `tests/test_bundle_cycle_atomic_refresh_go_r0734.py`;
- `tests/test_bundle_cycle_rolling_latest_policy.py`.

## Remaining gate

This record is AUTHORING evidence, not an independent verification result.
`R0733-REV-003` and `R0733-REV-004` remain `APPLIED_UNVERIFIED` until an
independent reviewer evaluates these exact candidate bytes and appends
`VERIFIED_CLOSED` or another authorized disposition. GO and v40.03r08 remain
blocked until that review and a separately authorized GO decision.
